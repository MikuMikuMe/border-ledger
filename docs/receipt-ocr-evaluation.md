# Receipt OCR evaluation

The public `docjay131/receipts-ocr-dataset` revision `ffb6088ef715689558289378fd26259f02f9910e` contains 230 images. Its labels were generated by a model and have not been independently verified. It is not a representative Canadian receipt test, and both halves were consulted during development; do not present results as an independent accuracy estimate. Keep a separately collected, manually labeled set for final evaluation.

## Android OCR

`ReceiptDatasetTest` is an opt-in instrumentation test. Without the `receiptDataset` instrumentation argument it skips. It reads `000.jpg` through `999.jpg` from a named directory under the test app's private files directory and writes `ocr.jsonl` there. Each row has an `id` and recognized `text`, or an `error`. It uses the same bundled ML Kit recognizer and text reading-order logic as the app. It bypasses the document scanner and does not test capture, image selection, or the UI.

Use an isolated debug package and a test device. Copy only images you are authorized to use into a new private directory with a name containing letters, digits, `_` or `-`. Run the test with `-e class com.lofuyu.borderledger.react.ReceiptDatasetTest -e receiptDataset <directory-name>`. Retrieve `ocr.jsonl` through `adb exec-out run-as <debug-package> cat files/<directory-name>/ocr.jsonl`. Remove the test images and result from the device when finished. OCR output may contain personal information; do not commit it or include it in logs.

## Scoring

With Node.js 22.18 or newer, run `node scripts/score-receipt-dataset.mjs <labels.json> <ocr.jsonl>`. It uses the shared production parser on each OCR result and prints aggregate counts only. The labels file is the dataset viewer's JSON array of records with `index` and JSON-encoded `text`. It reports labeled, exact matching, differing, and blank predictions separately for merchant, date, and total; missing labels and zero total labels are excluded. Merchant matching lowercases and retains only ASCII letters and digits, dates require exact matches, and totals are compared to two decimal places. Recognition errors are counted separately. It does not validate the dataset labels or distinguish OCR failures from parser failures.

For web comparisons, obtain OCR rows with the app's Tesseract.js version, English model and default segmentation; record runtime and worker configuration. Compare the same image bytes and OCR results before and after parser changes. Node results are not an end-to-end browser upload test. Do not send images to a remote provider without the product's explicit per-scan consent and an appropriate retention policy.

## Exploratory results, 2026-11-26

All 230 original images completed OCR on an x86-64 Android emulator using the instrumentation test. With the final parser, 92 of 225 labeled merchants matched (109 differed, 24 blank), 50 of 218 dates matched (1 differed, 167 blank), and 96 of 228 totals matched (15 differed, 117 blank). Rescoring the same text with the earlier parser gave 91 matching totals, 16 differing, and 121 blank. The app's document scanner and UI were not exercised in this run.

The earlier Node/Tesseract OCR of the same originals, rescored with the final parser, gave 35 of 225 matching merchants (86 differed, 104 blank), 32 of 218 matching dates (5 differed, 181 blank), and 63 of 228 matching totals (7 differed, 158 blank). The earlier parser matched 58 totals, with 7 differing and 163 blank. A grayscale and contrast-enhancement retry of 83 development images whose original total was blank produced 4 matching totals and 1 differing total; it was not adopted. These figures compare against unverified dataset labels, use data consulted during development, and do not establish production accuracy.
