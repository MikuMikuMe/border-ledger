# STRIDE security audit — reporting currency and locked FX

Date: 2026-10-14/15

Scope: Frankfurter ingestion, immutable purchase-date FX snapshots, reporting-currency selection, Chinese-bank settlement estimate, web/mobile clients, scheduled warming, and app-build CI changes.

## System boundary

The protected Worker reads the single-owner D1 ledger, fetches official Frankfurter daily EUR quotes, stores an immutable snapshot keyed by requested purchase/accounting date, and returns source totals plus optional converted totals. The web and Android clients validate and display the response; neither client contacts Frankfurter or calculates an exchange rate. A scheduled Worker invocation warms the current UTC date. The dashed Chinese-bank range is server-provided and is only emitted for eligible non-CNY Bank of China spending with complete conversion.

## Findings

| STRIDE category | Threat considered | Controls and evidence | Residual risk / owner |
|---|---|---|---|
| Spoofing | An unauthenticated caller reads or mutates ledger/reporting data, or a mobile device presents another owner's identity. | The Worker verifies Cloudflare Access JWT issuer, audience, and remote JWK signature before accepting the Access identity; the legacy API-key path uses a timing-safe comparison. Mutations require same-origin checks. Mobile routes use the existing owner/session and device-binding scopes. Report and preference routes are behind the same authorization gate. Evidence: `worker/index.ts`, `worker/mobile-auth.ts`, `tests/fx-routes.test.ts`, `tests/preferences-api-route.test.ts`, mobile auth tests. | Production deployment must keep `ACCESS_TEAM_DOMAIN`, `ACCESS_AUDIENCE`, `LEDGER_API_KEY`, and mobile auth secrets configured correctly. Deployment owner. |
| Tampering | A client changes a locked purchase date, substitutes a provider response, changes stored rates, or forges the ±1.5% band. | Inserts bind `fx_lock_date` from the canonical source date; updates/replays do not rewrite it. Migration 0018 backfills legacy rows and installs an immutability trigger. FX snapshots are first-write-wins by `requested_date`, validated against the shared registry, and checked with a SHA-256 content digest on read. The Worker computes conversions and the BOC band; web/mobile only map validated integers and render the server result. Evidence: `worker/migrations/0018-fx-snapshots.sql`, `worker/plaid.ts`, `worker/reconciliation-store.ts`, `worker/alert-ingestion.ts`, `worker/ledger-reports.ts`, focused FX and writer tests. | SHA-256 detects accidental or ordinary database tampering but is not a keyed authenticity mechanism against an attacker who can rewrite both fields. Restrict D1/Worker administration and add operational audit alerts. Operations owner. |
| Repudiation | The owner cannot explain which rate was used or whether a later provider refresh silently changed a historical total. | Each snapshot records requested date, effective date, provider, serialized validated rates, fetch time, and digest. Reports expose `lockedDateCount` and observed effective-date range. Same-date writes retain the first snapshot. Source transaction identity and provider/statement provenance remain separate from converted display totals. Evidence: `worker/db-types.ts`, migration 0018, `tests/fx-snapshot-migration.test.ts`, `tests/ledger-reports-fx.test.ts`, `tests/fx-scheduled.test.ts`. | There is no external signed receipt from Frankfurter and no user-facing audit history for every report read. Retain the immutable snapshot and consider append-only operational logs if formal dispute evidence is required. Product/operations owner. |
| Information disclosure | Provider failures or client errors leak rate payloads, secrets, or raw notification data; a browser bypasses the intended private boundary. | Frankfurter requests use a fixed HTTPS origin, bounded 10-second timeout, bounded 64 KiB body, bounded JSON depth/count, and safe error names; provider response bodies are never logged. Clients receive report data only after the protected API responds and do not receive provider credentials. The debug FX preview activity is in the debug manifest only; the release APK manifest contains no preview activity or action. CI has `contents: read` and no signing secrets. Evidence: `worker/fx-rates.ts`, `worker/index.ts`, `android/src/debug`, `.github/workflows/app-build.yml`, `aapt2` release-manifest check, provider/scheduled logging tests. | Browser/API logs, Cloudflare Access configuration, D1 backups, and Android system screenshots remain deployment responsibilities. Do not enable debug builds for distribution. Release owner. |
| Denial of service | A provider hangs or sends a huge/malformed payload; a report causes unbounded rate fetches; a scheduled failure prevents normal ledger reads. | Provider fetches abort after 10 seconds, bodies are capped, JSON values/depth/rate rows are capped, and one snapshot is reused per lock date. Scheduled provider failures are logged by safe error name and do not rewrite existing snapshots; database failures are not mislabeled as provider outages. Reports degrade to partial/unavailable conversion while source totals remain available. Evidence: `worker/fx-rates.ts`, `worker/ledger-reports.ts`, `worker/index.ts`, `tests/fx-rates.test.ts`, `tests/fx-scheduled.test.ts`, `tests/ledger-reports-fx.test.ts`. | There is no new explicit per-owner report rate limit in this feature. Apply Cloudflare/platform rate limiting and monitor D1/Frankfurter latency in production. Operations owner. |
| Elevation of privilege | A caller injects an unregistered currency, unsafe amount, alternate registry, or backend-only change into an app build; a debug-only screen becomes a release capability. | Currency codes are accepted only from the checked-in 162-entry ISO registry; the WeChat/BOC parser, provider parser, and conversion path all validate against that registry, while the provider conversion ignores caller registry-shaped overrides. Monetary/count values are safe integers, rates are positive validated rationals, and unknown/unsafe/decimal contract values are rejected by clients. App CI path filters exclude `worker/**` and other backend-only paths while including Android/web/contracts; workflow permissions are read-only. Release APK inspection shows no `FxReportPreviewActivity` or `FX_REPORT_PREVIEW`; debug APK inspection shows the activity only in debug. Evidence: `contracts/currencies.json`, `android/.../CurrencyRegistry.kt`, `android/.../BocCreditCardParser.kt`, `src/domain/currencies.ts`, `worker/fx-rates.ts`, `src/App.tsx`, Android decoder tests, workflow-path tests, `aapt2` manifest checks. | Frankfurter may not publish a quote for every ISO registry code. The system fails closed for that source/date and reports an unavailable/partial source code; it must not silently substitute another provider or live rate. Product owner should communicate provider coverage in the UI/ops docs. |

## Security verification performed

- The current checkout's focused web suites passed: UI/navigation/currency (14 tests), FX/reporting/scheduled routes (39 tests), security/auth/preferences/workflow (18 tests), plus the workflow-path contract (2 tests). TypeScript typecheck and the production web build passed.
- `npm audit --omit=dev --audit-level=high` reported no production dependency vulnerabilities.
- Android `:app:testDebugUnitTest :app:lintDebug :app:assembleRelease` passed locally. The release artifact is intentionally unsigned in this local gate; release signing remains protected by the owner-controlled workflow.
- A real Chrome headless DOM smoke loaded the built application shell, verified the Border Ledger title, and verified the dark theme metadata. Interactive Chrome CDP/Tabbit control was unavailable in this environment; target, source-lane, CNY-exception, and dashed-band behavior are covered by the focused UI/FX tests rather than being claimed from an interactive browser session.
- The physical USB target was not present in the final verification (`adb devices -l` returned no device). The Android AVD could not boot because Windows hardware acceleration is disabled for the x86_64 image. No device screenshot, install, or crash-buffer result is claimed for this final checkout.
- Workflow path contract: 2 tests passed; backend-only representative paths do not match the app workflow. The app workflow has read-only contents permissions and allowlisted Android/web/contracts paths.

## Decision

No high-severity security finding was found in the feature implementation. The local static/native/browser evidence is green, with the device/interactive-browser limitations above. Normal production operational controls remain for Access, D1, rate limiting, and release signing.
